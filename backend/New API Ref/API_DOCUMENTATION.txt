- DATABASE_URL OR DB_HOST/DB_PORT/DB_NAME/DB_USER/DB_PASSWORD: PostgreSQL connection.

No endpoint returns secrets, database connection settings or role credentials.

SHARED HTTP CONTRACT / SECURITY
-------------------------------
JSON requests: Content-Type: application/json; Accept: application/json.
Owner calls: Authorization: Bearer <latest opaque Node access token>.
Tokens are opaque 43-character base64url credentials, not JWT authorization claims.
Do not send a client user_id to select ownership; it comes from the authenticated
session. Owner database access uses transaction-local identity + RLS policies.
Admin probe additionally checks mss.user_roles. Production startup rejects unsafe
DB owners/superusers/BYPASSRLS/role-creation/schema-creation privileges.

JSON limit64KiB, compressed request bodies not accepted. Write helpers reject
unknown top-level fields; profile/business validation allowlists nested fields.
GET scheme bodies are explicitly rejected; all other GET callers should omit body.
Do not assume all read endpoints reject every unused query key: strict per-route
validation is specified in each entry. JSON {} differs from an absent request body.
Responses are unwrapped. Empty paginated feeds return200 with items:[] and
next_cursor:null. 204 and304 have no JSON body. Bundle download is raw gzip bytes.
Private responses use no-store. Public catalog has documented ETag/cache behavior.
X-Request-ID is generated server-side. It is a response HEADER, not a guaranteed
JSON field. Current errors: {"error":"CODE"}, optionally details:[{field,code,...}].
No global message/request_id/data envelope. Health failure has its own body shape.
Unexpected failures are500 INTERNAL_ERROR. Hosted startup failure503
SERVICE_UNAVAILABLE may occur before application request headers are initialized.
Parser errors:400/413/415 INVALID_REQUEST. Write media errors415 JSON_REQUIRED.
Unknown URL/method combinations return404 NOT_FOUND. Production HTTP426 HTTPS_REQUIRED.
Never log body, query, auth headers, exception stacks, SQL or personal identity.
Retain safe status/request ID for troubleshooting. Existing fixed security/startup
events are intentional operational logs, not disposable debugging output.

Quotas: global120/minute/IP (health bypass); /auth additionally20/minute/IP local
and30/minute/IP database-backed (including password login/logout operations).
Password login adds10/minute/IP + normalized email; owner password5/minute/owner.
Profile, notifications, schemes each60/minute/owner. Admin20/minute/owner.
Account deletion has its own3 attempts/minute/owner quota, in addition to global limits.
Favorites/eligibility results share60 requests/minute/owner (LIBRARY_RATE_LIMITED).
Support guest10/minute/IP; support submission has additional hourly/cooldown rules.
429 returns Retry-After seconds; honor it. Shared quota-store outage503
AUTH_TEMPORARILY_UNAVAILABLE fails closed. Applicable module quotas are cumulative.

Integration guidance only: this change does not modify Flutter application code.

   Idempotency-Key for retries of one submission. Do not send both identities.
8. Optional local password setup/change/remove requires recent authentication;
   success revokes all sessions and requires fresh sign-in.
9. Logout/revoke session clears tokens, subscriptions and private offline data.
10. Delete account: DELETE /v1/me with bearer, no query/body. Requires authentication
    within5 minutes, not merely a refreshed token. On403 reauthenticate explicitly;
    on204 clear private device data and remain signed out. This is a permanent
    Node account deletion, not logout. Google and unmigrated external data are
    outside its scope. Do not automatically sign in after a lost delete response.
11. Saved favorites: GET /me/favorites to restore canonical IDs; PUT
    /me/favorites/:id with no body to save; DELETE same canonical ID to remove.

    content still follows scheme API permissions. Max500 favorites per owner.
12. Eligibility persistence: GET /me/eligibility-results, retain ETag; PUT exactly
    {"scheme_ids":["<visible-scheme-id>"]} with X-Eligibility-If-Match. Empty []

    This stores client results, not server-certified eligibility. It does not
    modify favorites and is read separately from ProfileAggregate.
    Offline writes are queued locally and replayed online with current identity,
    state and version. Never reuse a previous account's queue or silently overwrite.

import 'dart:convert';
import 'package:http/http.dart' as http;

class Api {
  Api(this.origin, this.client);
  final Uri origin; // e.g. Uri.parse('http://10.0.2.2:3000')
  final http.Client client;
  Future<http.Response> call(String method, String path, {
    String? accessToken, Map<String,String> query = const {},
    Map<String,String> headers = const {}, Object? body,
  }) async {
    final uri = origin.resolve(path).replace(queryParameters: query.isEmpty ? null : query);
    final request = http.Request(method, uri);
    request.headers.addAll({'Accept':'application/json', ...headers});
    if (accessToken != null) request.headers['Authorization'] = 'Bearer $accessToken';
    if (body != null) {
      request.headers['Content-Type'] = 'application/json';
      request.body = jsonEncode(body);
    }
    final streamed = await client.send(request).timeout(const Duration(seconds:30));
    return http.Response.fromStream(streamed).timeout(const Duration(seconds:30));
  }
}

NOTIFICATION REALTIME + PUSH - HOW IT WORKS
------------------------------------------
Backend producer -> committed notification -> DB trigger -> owner event log and
durable device outbox -> SSE client / separate FCM worker -> authenticated inbox.

1. Apply migration014_notification_delivery.sql AFTER earlier migrations. Apply
   deployment/notification-delivery-runtime-grants.sql as the database administrator.
   HTTP runtime gets owner-scoped event/device reads, registration-broker EXECUTE,
   admin-routed notification INSERT and idempotency receipts, not push-job access.
   Provision a separate restricted login with mss_push_worker membership.
   Production HTTP startup rejects membership in the worker group as well as
   table ownership/superuser/DDL privileges. Never combine the two login roles.
   Production worker/cleanup startup also requires the restricted worker membership
   and rejects table ownership/superuser/DDL privileges.
2. Enable FCM HTTP v1 in the Firebase project; give the server service account send
   permission. Configure Application Default Credentials (e.g.
   GOOGLE_APPLICATION_CREDENTIALS pointing outside the repository). Set FCM_PROJECT_ID
   and PUSH_TOKEN_ENCRYPTION_KEY: secret base64-encoded32 random bytes shared by HTTP
   registration and worker. Never document its value or service-account JSON.
   No legacy server key/admin secret belongs in Flutter.
3. Worker-only PUSH_DATABASE_URL selects the restricted worker login; use verified
   DB TLS in production. Run npm run push:work as a supervised separate process,
   or npm run push:work -- --once from a suitable scheduler. Claims4 jobs/batch with
   SKIP LOCKED,60s recoverable leases; idle loop1s. HTTP starts no background daemon.
   Without the worker inbox/SSE work, but no background push leaves the queue.
4. Flutter team configures Firebase Messaging, obtains OS notification permission,
   receives SDK registration token and PUTs /me/push-devices/:id with a local UUID
   and Node bearer. Re-register on SDK token rotation/fresh login. iOS needs APNs
   setup and app capabilities. Endpoint supports android/ios only. This backend
   does not modify mobile code or grant OS permission. Follow current SDK docs.
5. Staff publishes POST /admin/notifications using a persistent idempotency UUID.
   Committed INSERT creates owner-ordered event + job per active-session device.
   No registration means no job; app can still fetch inbox. Registration never
   sends old notification history. Read/delete changes emit hints, not new pushes.
6. Foreground SSE polls committed events2s, heartbeat10s, bounded stream~25s.
   Reconnect with jitter1..5s and Last-Event-ID using a streaming HTTP client.
   ready/reset/change hints require REST inbox/count refresh. Persist cursor AFTER
   handling/refetch. Session/token rechecked each poll; logout/refresh/expiry closes
   the old stream. Expired7-day history returns reset/full refetch. Concurrent
   processes use committed per-owner sequence ordering, not a process-local bus.
   Limits50 streams/process,2/owner plus shared notification quota60/minute. Disable
   proxy buffering; test actual host streaming/timeouts. Push/SSE can overlap, so
   deduplicate by notification_id. Cancel stream on background/logout.
7. Background worker checks generation, active session, unread state and current
   profiles.notifications before each send. false suppresses push, not inbox/SSE;
   absent profile uses existing true default. FCM payload: generic MSS/new-update
   notification plus inbox UUID only. Full text is fetched with current owner auth.
   Wrong-account clients cannot fetch private content. No automatic scheme-change
   campaign exists: a trusted backend producer must choose recipients/message.
8. UNREGISTERED removes only matching device generation.429/5xx/network/auth errors
   back off from60s with jitter/Retry-After, max8 attempts/24h job age. Other provider
   rejections become dead jobs. FCM TTL1h. Acceptance does not prove display/viewing.
   At-least-once delivery can duplicate after a send/ack crash; UUID/collapse/tag
   support deduplication. Do not delete tokens on every400; UNREGISTERED is specific.
9. Logout/session revocation removes session devices/jobs; account deletion cascades
   all new private tables. Already accepted/in-flight generic pushes cannot be
   recalled. Re-registering the same physical token to a new authenticated account
   atomically transfers it and removes old queued jobs. Device IDs alone cannot
   transfer foreign tokens. Stable encryption key required; plan key rotation and
   re-register/re-encrypt devices rather than silently changing it.
10. Schedule npm run push:cleanup daily with worker-only credentials: event retention
    7days, completed/dead jobs7days, expired/revoked session devices removed. Keep
    event sequence heads monotonic. Publish receipts remain until actor/recipient
    account deletion so retries do not recreate a deleted inbox notification.

Usage / Flutter integration:

After explicit user intent to delete, send DELETE /v1/me with a current bearer and no body. On

caches/offline snapshots and return to signed-out state. Linked support tickets are

Sample JSON request:

No body.

Sample response:

No JSON success body.

200 text/event-stream, not JSON. Frames: id: <cursor> / event:

{"notification_id":"<UUID>"}, followed by blank line. ready/reset controls include

Usage / Flutter integration:

Use streaming HTTP, not buffered Api.call. Refetch inbox/unread count on ready,reset and
notification events; persist cursor only after handling/refetch. Streams end around25s;
reconnect with jitter1..5s and latest token/cursor. DB polling2s, heartbeat10s; token/session
rechecked each poll. Refresh/revocation closes old stream. Expired/pruned7-day history returns
reset and needs full refetch. Per-owner committed sequences avoid global-sequence late-commit
gaps. Caps50 streams/process,2 per owner; shared quotas also apply. Slow clients disconnected.
Disable proxy buffering and test host timeouts. No sticky sessions/in-memory event bus
required. Stream carries no notification text.

// Check status. For200 parse stream with utf8.decoder and LineSplitter.

async function bounded(action) {
