API OVERVIEW
GET /v1/catalog/current                 -> JSON object or null; update discovery
GET /v1/catalog/releases/:tag           -> JSON object; original release details
GET /v1/catalog/releases/:tag/bundle    -> binary gzip; catalog payload
All three are public GET APIs. No login, query parameters or request body.
No POST /catalog or Flutter publish API exists. Backend operators own publishing.

PURPOSE
The app already browses/searches/recommends schemes using its offline bundle.
These APIs replace the Supabase current-release RPC and Storage download only.
No profile answers or scheme search form are submitted to these endpoints.
Flutter source was not modified. The frontend team implements the source adapter.

BASE URL
Local: http://127.0.0.1:5000
Production target: https://api.msmeschemes.org (deployment not verified).
Physical phone: use the development computer's reachable LAN address.
Standard Android emulator host alias: http://10.0.2.2:5000.
All routes public; no bearer token, body or Content-Type required for GET.
Normal API-wide quota is 120 requests/minute/IP; 429 RATE_LIMITED + Retry-After.
Production HTTPS enforcement still applies.

1. GET /v1/catalog/current
Collect from app: optional last received ETag, sent as If-None-Match.
200 returns ONE object, not an array and not {data:...}:
{
  "release_version": "1.35.1-alpha",
  "schema_version": 1,
  "package_sha256": "cea438e919356453210a03afaf5f65e9c83dbec856a9767323b42804b92ee619",
  "package_byte_size": 713188,
  "record_counts": {"scheme_catalog.json": 171},
  "published_at": "2026-10-16T00:00:00.000Z",
  "bundle_url": "/v1/catalog/releases/1.35.1-alpha/bundle"
}
Example is illustrative; actual record_counts contains all catalog counts and
published_at is the pointer publication time, not source release creation time.

Field types:
release_version: string; stable release tag, never compare lexicographically.
schema_version: integer; major of original schemaVersion ("1.0.0" -> 1).
package_sha256: string, 64 lowercase hexadecimal characters; compressed bytes hash.
package_byte_size: positive integer; exact compressed byte count.
record_counts: object mapping catalog filenames to nonnegative integer counts.
published_at: string, UTC ISO-8601 timestamp.
bundle_url: string, API-origin-relative download path. Resolve against BASE URL.
Do not concatenate it with a base URL already containing /v1.

No published pointer: HTTP 200 with JSON null. Keep installed/factory catalog.
Do not infer an active release from imported rows, import time or highest tag.
ETag is a quoted SHA-256 of the current JSON representation, not the bundle hash.
Cache-Control: public, max-age=60, must-revalidate.
If-None-Match matching normal revalidation: 304, empty body; keep cached manifest.
Do not JSON-decode a 304 response. An explicit request Cache-Control: no-cache
may force 200; normal conditional checks can send Cache-Control: max-age=0.
Malformed stored published metadata: 503 {"error":"CATALOG_UNAVAILABLE"}.
Database/unexpected failure: 500 {"error":"INTERNAL_ERROR"}.

2. GET /v1/catalog/releases/:tag
Path tag: string, URL-encode as one path segment.
200: original immutable release.json, camelCase keys preserved:
releaseId, releaseTag, schemaVersion (string), releasedAt, bundleAsset,
bundleBytes, bundleSha256, uncompressedBytes, entityCount, searchIndexCount,
recordCounts and perFileSha256.
This is NOT the snake_case current-manifest response. bundleAsset is a source
asset reference, not the HTTP download URL. Use current.bundle_url instead.
ETag hashes this JSON representation. Matching revalidation returns 304.
Cache-Control: public, max-age=31536000, immutable.
Unknown tag: 404 {"error":"RELEASE_NOT_FOUND"}.
Imported snapshots are public by known tag, as before. Import does not announce
an update; the explicit pointer controls discovery. Do not put private data in
public catalog snapshots.

3. GET /v1/catalog/releases/:tag/bundle
200 application/gzip, raw gzip file bytes; NOT JSON and not base64.
No Content-Encoding: gzip: the gzip file is the downloadable artifact itself.
ETag is the quoted package_sha256; normal matching revalidation returns 304.
Cache-Control: public, max-age=31536000, immutable.
Unknown tag: 404 {"error":"RELEASE_NOT_FOUND"}.
Save bytes, verify length + SHA-256, THEN decompress with a bounded output limit.
Do not hash decoded JSON or a transport-recompressed file. Proxy/CDN configuration
must preserve exact artifact bytes. Download once at a time, keep prior catalog
until all integrity/schema/install checks pass. A 304 download requires cached
artifact bytes; without them retry without If-None-Match.

FLUTTER INTEGRATION SEQUENCE
1. Keep current offline catalog usable; run update checks in the background.
2. GET current. On null/304/offline/error retain the current installed bundle.
   For 304 use the previously cached manifest only if present.
3. Parse a 200 object with CatalogManifest.fromReleaseRpc(jsonObject).
   Keep bundle_url separately; CatalogManifest currently does not store it.
4. Compare release_version + package_sha256, not version/tag ordering.
5. Check schema_version against SchemeCatalogStore.supportedSchemaVersion.
   Unsupported major: retain existing bundle and show app update guidance.
6. Resolve bundle_url against the configured API origin and GET bytes.
7. Before installation, enforce compressed size, bounded decompression and
   parsed catalog structure/count checks in the frontend adapter. The current
   SchemeCatalogStore.install verifies SHA-256 and schema compatibility, writes
   release files, then updates the pointer; it does NOT itself enforce byte size,
   decompression bounds or parsed catalog counts. Do not assume these are covered.
8. Reuse SchemeCatalogSyncService single-flight, timeout and hourly throttle.
   On rejection preserve installed catalog; do not replace local browsing with
   online GET /schemes calls.

From mss-backend:

  npm run catalog:check
  npm run catalog:import
  npm run catalog:publish -- 1.35.1-alpha
  npm run catalog:verify

catalog:publish validates stored gzip checksum, size, decompressed size, record
counts, duplicate IDs and DTO metadata, then swaps pointer in one transaction.
Same-tag publish preserves publication timestamp. Publishing a previous validated
tag rolls back discovery to that snapshot; old artifact bytes are retained.
This CLI is a deployment operation, not a Flutter endpoint or full editorial
approval/permission/audit workflow. It does not certify full semantic relations,
localization correctness or compatibility with every app build; editorial review
and staging/device checks remain required before production publication.

Original release field types:

releasedAt         string; source release UTC date/time

bundleBytes        integer; compressed package size
bundleSha256       string; compressed package SHA-256
uncompressedBytes integer; expected decompressed package size
entityCount        integer; catalog entity count, excludes search index rows
searchIndexCount   integer; search index row count
recordCounts       object<string, integer>; per-catalog row counts
perFileSha256      object<string, string>; catalog filename -> SHA-256

Do not deserialize this endpoint using CatalogManifest.fromReleaseRpc: that
factory expects GET current's snake_case representation. Raw release details
are useful for diagnostics and optional extra download metadata validation.
If fetched for installation, ensure releaseTag, bundleSha256 and bundleBytes
match the selected current manifest. JSON key ordering has no semantic meaning.

APPENDIX B - FRONTEND IMPLEMENTATION RECIPE
This is implementation pseudocode, not a drop-in tested Dart adapter.

Configuration:
  apiOrigin = Uri.parse('https://api.msmeschemes.org'); // production target
  // Development: http://127.0.0.1:5000 on desktop.
  // Keep API origin configurable; do not hardcode production during testing.

fetchCurrentManifest():
  GET apiOrigin.resolve('/v1/catalog/current') with an explicit timeout.
  Send Accept: application/json.
  Send If-None-Match only when BOTH cached ETag and its manifest/null exist.
  For conditional requests, use Cache-Control: max-age=0.
  If 304: return cached manifest (which may be null); do not decode a body.
  If 200: decode JSON. If null, cache null with its ETag and return null.
  Otherwise validate expected types, parse CatalogManifest.fromReleaseRpc,
  and keep bundle_url alongside that manifest. Cache body and ETag together.
  Reject invalid/missing fields; never replace installed catalog on parse error.
  On other statuses: map errors below; keep installed/factory catalog available.

fetchPayload(manifest):
  Resolve the matching cached bundle_url against apiOrigin.
  Require the same scheme/host/port as apiOrigin and the expected catalog path.
  Avoid redirects to unapproved origins. No bearer token is needed.
  GET as bytes (for package:http, use response.bodyBytes, not response.body).
  Require HTTP 200; parse JSON errors only when the response is an error.
  Enforce byte cap while downloading, matching package_byte_size after download.
  Verify SHA-256 on the exact downloaded gzip bytes.
  Enforce an agreed decompression cap and validate expected catalog data.
  Return bytes for SchemeCatalogStore.install(manifest, bytes).

The existing CatalogReleaseSource interface returns CatalogManifest only; the
HTTP implementation must retain the matching bundle_url internally, keyed by
release identity/hash, or introduce an agreed descriptor in the frontend.
Do not retain one global URL that can be mismatched with another manifest.

Suggested frontend components:
- HttpCatalogReleaseSource implements CatalogReleaseSource.
- fetchCurrentManifest replaces Supabase RPC access.
- fetchPayload replaces Supabase Storage access.
- Inject this source into SchemeCatalogSyncService.
- Keep its single-flight behavior and hourly throttle.
- Apply retry/backoff only to safe GET requests; honor Retry-After on 429.
- Mobile lifecycle/resume checks must not trigger repeated parallel downloads.
- Do not disable normal offline browsing while checking for updates.

APPENDIX C - UI / ERROR HANDLING
200 object: valid current release; compare identity/hash and download if changed.
200 null: no published release; keep factory/installed catalog, no blocking error.
304: cached representation unchanged; no JSON body.
404 RELEASE_NOT_FOUND: keep old catalog; recheck current later.
429 RATE_LIMITED: honor Retry-After; keep old catalog.
503 CATALOG_UNAVAILABLE: backend metadata needs attention; retain old catalog.
500 INTERNAL_ERROR / network timeout: retain old catalog and retry later.
426 HTTPS_REQUIRED in production: correct API URL/proxy HTTPS configuration.
Unsupported schema: retain old catalog; guide user to an app update.
Hash/size/structure failure: reject downloaded file; retain old catalog.
The error body is JSON {"error":"CODE"}; a gzip success response is binary.
Never decode all responses using the same JSON handler.
